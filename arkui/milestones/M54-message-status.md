# M54 · 发送消息状态与持久化

Flutter 消息页在开始发送时创建记录，并保留失败、拒绝、取消结果；此前原生版只在成功后写历史，且会话气泡固定显示“已发送/已接收”。

现在发送开始即创建稳定 ID 的文字或文件记录，按等待、发送中、完成、跳过、拒绝、失败、取消更新原记录。部分批次成功后失败时保留每个文件的实际结果。会话、历史和详情使用相同状态标签，显示失败原因；正在传输的气泡可打开传输任务。导入的旧失败/取消记录也不再显示为成功。

历史更新尊重用户选择：发送期间删除记录不会在完成时重建；关闭保存历史后开始的任务，即便途中重新打开开关也不写入持久记录。重启时把本机未完成的发送记录标为中断，避免永久显示发送中。状态更新只发生在阶段变化，不随进度频繁写盘。

## 验证

- 独立 HTTP 对端实际收发，验证等待状态落盘、拒绝、批次部分失败、取消、同一 ID 更新、发送中删除、临时历史及未完成记录重启恢复。
- 全部 30 个主机测试文件通过，包括大文件 HTTPS 背压、双端取消、Flutter 数据导入与历史保存。
- ArkTS 和 HAP 构建成功，未访问设备。接收中的批次状态持久化仍属后续工作，本里程碑不宣称完整消息批次等价。
