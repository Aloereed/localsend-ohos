# M48 · HTTPS 突发接收与终止恢复

移除 TLS 密文的逐包 Promise 队列，在 socket 回调中同步解密，合并大包按 64 KiB 分片输入原生引擎。旧代码可被超过 2 MiB 的连续回调稳定触发“TLS 输入队列已满”；修复后真实 MbedTLS 与独立 TLS 客户端的两种突发模式均完整接收并通过 SHA-256 校验。

接收异常立即终止会话并撤销全部旧令牌，先发布终止状态再等待文件写入及清理；未开始的文件同步结束。上传初始化失败和取消竞态也执行同一清理流程。主动取消及异常中断向发送方通知取消，记录应答或失败原因；发送失败也通知已建立会话的接收方，避免残留忙碌状态。

验证：26 个测试文件全部通过，包括 27 组服务互通、128 MiB 非零 HTTPS 文件、HTTP/HTTPS 取消通知、慢清理期间立即重新接收、9 组浏览器分享测试。ArkUI Debug 构建成功。

设备当前安装 2.0.45；未安装此包，实际设备上的 HTTPS 大文件仍需复测。此处确认的是可复现的代码缺陷及主机回归，不据此宣称所有设备故障均已排除。
