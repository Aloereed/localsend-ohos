# M78 · 发送文件的错误归属

发送任务中某个文件失败后，原先所有未完成历史项都继承同一个任务错误，尚未开始的文件看起来也像发生了相同读写故障。现在活动文件记录实际失败原因，后续等待文件说明“任务已停止，此文件尚未开始传输”。准备请求本身失败时仍保留该请求的错误原因。完成和跳过文件不添加错误。

文件行显示其原因，任务和文件错误文字支持复制。发送历史优先使用逐文件原因。新重试任务创建干净的文件状态，成功后不携带旧错误。

真实 HTTP 单文件重试测试增加错误归属及历史断言；服务集成和消息状态回归通过，共三个测试文件。ArkTS 和原生未签名构建成功。未访问设备。接收端仍以会话错误为主，本轮未改变接收终止逻辑。
