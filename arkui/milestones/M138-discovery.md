# M138 · 发现恢复、扫描兜底与双栈组播

版本 2.0.138 / 2000138，包含 M137 的客户端 TLS 身份和手势条设置。依据 [发现对照](../discovery-audit-20260910.md) 修复六项差异。

## 最终行为

- 发现 socket 按有效接口维护。加入失败、运行中失败在后续刷新重试；换网移除旧接口、增加新接口；回前台强制重建发现 socket。单个网络属性读取失败不会阻止其他网卡。恢复发现不重启文件传输监听。
- 为补足 NetworkKit 缺少出站组播网卡选择，新增独立 multicast_bridge.cpp：逐接口加入 IPv4/IPv6 组播，明确选择出站接口，bind 前设置复用，保留 IPv6 scope，限制单包及事件队列，关闭确认后再重建。出站 TCP/TLS 及 IPv4 HTTP 接收继续使用 NetworkKit。
- 组播和收藏探测启动后等待 1.5 秒，无新确认时扫描有效接口所在 /24 与实际前缀的交集，排除本机及网络/广播地址。全局最多 16 个扫描探测，自动扫描间隔至少 60 秒，重复刷新共享扫描。未知目标分别尝试 HTTPS/HTTP；已知身份继续固定协议/指纹，不降级绕过身份检查。隐藏状态不广播、不注册，允许只读查询对方信息。
- 停止服务、换网取消旧扫描和发现请求；有活动传输时不启动扫描，扫描途中发现活动传输也取消。迟到 socket 回调和过期网络刷新不复活旧发现。
- 旧 HTTP 记录纠正成 HTTPS 后补发 register，使对方也能发现本机；兼容无旧 announce 标记的 v2.2 数据报，并合并正在进行的相同注册。
- IPv4 之外增加 IPv6 HTTP/HTTPS 接收，TCP 原生背压服务支持 IPv6-only bind 及 scope。IPv6 接收可用后才加入 IPv6 组播。新增 IPv6 子网判断，接口筛选不再把所有 IPv6 消息直接排除。

## 验证

68 个主机测试文件已通过：66 个原有及新增测试在完整批次执行，新增 discovery-stages 单独执行；discovery-native 在允许本机组播的进程内执行。普通沙箱阻止组播收发，放行后实际回环成功，没有把沙箱内超时当作功能通过。

- discovery-recovery：逐接口加入、部分失败不影响其他接口、刷新重试、前台重建、IPv6 同接口去重、已退出回调过滤、关闭竞态、枚举失效网络后仍读正常 Wi-Fi、HTTPS 双向注册、隐藏状态。
- discovery-scan：/24、/30、/31、/32 与较大网段边界、去重、过滤、16 并发、HTTP/HTTPS 混合、冷却、指纹拒绝、取消。
- discovery-stages：刷新合并、确认后不升级扫描、前台重建参数、换网取消、停止后不扫描。
- discovery-native：本机回环与实际局域网两个源接口真实组播收发、端口共享、6 次关闭重建、已退出句柄拒绝；IPv6 实际加入/发送/接收且 scope 保留。
- discovery-ipv6：IPv4/IPv6 同时监听，HTTP 和 HTTPS 各完成双向发现与 1 MiB+17 字节文件传输，接收文件逐字节一致，本机和对方加密设置相反，句柄归零。
- 既有 TLS、发送/重试、取消、接收背压及窗口等回归通过；鸿蒙 debug 编译通过，native-host 编译通过。
